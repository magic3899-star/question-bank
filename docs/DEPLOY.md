# 배포 안내

## 설치 파일 만들기 (개발자)

```
npm run dist
```

`release/QuestionBank-Setup-<버전>.exe` 가 만들어진다. 버전은 `package.json` 의 `version` 을 따른다.
(`npm version <새 버전> --no-git-tag-version` 으로 올린다.)

## 직원 설치 방법

1. 받은 `QuestionBank-Setup-<버전>.exe` 를 더블클릭한다.
2. 파란 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행** 을 누른다.
   (코드 서명 인증서가 없는 프로그램이라 처음 한 번만 나온다. 바이러스가 아니다.)
3. 설치 위치를 고르고(기본값 그대로 OK) 설치를 마친다. 바탕화면과 시작 메뉴에 "문제은행" 바로가기가 생긴다.
4. 관리자 권한이 필요 없다(내 계정에만 설치).

## 데이터 위치와 백업

- 문제·설정은 `%APPDATA%\QuestionBank` 에 저장된다. 프로그램을 지우거나 새 버전으로 업데이트해도 남는다.
- 하루 한 번 자동 백업(최근 10개). **설정 → 백업과 복원** 에서 지금 백업하거나 되돌릴 수 있다.
- 다른 PC로 옮기려면 그 폴더의 `data/bank.sqlite` 를 복사한다.

## 수정 → 업데이트 흐름

1. 직원이 써 보고 고칠 점을 알려 준다.
2. 개발자가 코드를 고치고 테스트를 통과시킨다. `package.json` 의 버전을 올린다(`npm version patch --no-git-tag-version`: 1.0.0 → 1.0.1).
3. 커밋하고 `git push` 한다.
4. `npm run release` 한 번이면 설치 파일을 만들고 GitHub Releases 에 `v<버전>` 으로 올린다.
   (커밋 안 된 변경이 있거나 push 가 안 됐거나 같은 버전이 이미 있으면 알려 주고 멈춘다.)
5. 직원 PC 는 프로그램을 켜고 5초 뒤 새 버전을 확인해 **자동으로 내려받고**, 프로그램을 **닫을 때 설치**한다.
   바로 받고 싶으면 **설정 → 업데이트 → 지금 확인**, 받은 뒤에는 **다시 시작해 업데이트** 를 누른다.
   프로그램 위쪽에 "새 버전이 준비되었습니다 · 지금 다시 시작" 띠도 뜬다.

문제 데이터(`%APPDATA%\QuestionBank`)는 업데이트해도 그대로 남는다. 새 버전에 DB 구조 변경이 있으면 프로그램이 처음 열 때 자동으로 바꾼다.

## 자동 업데이트 전제

- 저장소가 **public** 이어야 직원 PC 가 인증 없이 확인할 수 있다. 문제 데이터는 저장소에 없으므로(.gitignore, 이력도 확인함) public 이어도 안전하다.
  private 인 동안은 확인이 실패하며(설정 화면에 안내), 프로그램 사용에는 지장 없다. 이때는 설치 파일을 직접 전달한다.
- 릴리스에는 설치 파일(`.exe`), `.blockmap`, `latest.yml` 세 파일이 모두 있어야 한다(`npm run release` 가 올린다).
- 릴리스 파일에는 문제 데이터를 넣지 않는다(공개이므로). 기본 문제는 배포 묶음의 `data/bank.sqlite` 로만 전달한다.
- 코드 서명이 없어 업데이트 설치 때도 Windows 가 경고할 수 있다.

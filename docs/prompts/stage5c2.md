## 5C2단계: 편집기 다듬기(디자인 시스템 준수) + 붙여넣기 줄 잇기·해설 정답 추출 + 캡처 도구 보강

검수자가 실제 문제 DB 와 "PDF 에서 복사한 듯한" 글(문장 중간 줄바꿈, 한 줄에 몰린 선지, 쪽 번호)로 앱을 실행해 확인했다. 기능(분리·미리보기)은 정상이다. 아래만 고친다.

## 실행 방식
- 계획만 말하고 멈추지 마라. 구현하고 검사를 통과시킨 뒤에만 보고하라. 사용자에게 묻지 마라.
- AGENTS.md, docs/DESIGN.md, docs/STAGE5B.md·STAGE5C.md, `src/app/**`, `src/modules/importers/text/**`, `src/modules/layout-parser/**` 를 `Get-Content -Encoding UTF8` 로 읽고 시작. 계약 수정 금지. 실제 문제 파일·`.tmp-realcheck/` 접근 금지. 네트워크 설치 금지. Electron 실행·캡처는 하지 말 것(검수자가 함).
- 마무리 전 `npm.cmd test`(전체), `typecheck`, `lint:deps`, `format`→`format:check`, `build` 모두 통과.

## 5C2-1. 디자인 시스템을 벗어난 기본 컨트롤 교체 (DESIGN.md §5)
 a. 과목·등급 등 **기본 `<select>`** 가 작고 토큰을 따르지 않는다 → `components/Select.tsx`(+ module.css): Input 과 같은 높이·테두리·반경·포커스 링, 라벨 위, 다크 모드, 키보드 접근. 앱 전체의 기본 select 를 이것으로(가져오기 옵션 패널·검수 표 등급 포함).
 b. 이미지 추가의 **기본 파일 입력**("파일 선택 / 선택된 파일 없음") → 보조 Button("이미지 추가") + 숨은 input. 끌어놓기·붙여넣기 안내 문구는 유지.
 c. 서식 도구 막대의 글자 버튼(밑줄 U·굵게 B…) → lucide 아이콘 버튼(Underline, Bold, Italic, Superscript, Subscript) + `aria-label` + 툴팁(단축키 표기), 눌린 상태(`aria-pressed`) 표시.
 d. "목록에서 고르기" 를 학습목표 입력란 **오른쪽에 붙은 버튼**(입력 그룹)으로.
 e. **편집 모드(`edit?id=`)에서는 "PDF 붙여넣기" 패널을 접어 둔다**(펼치기 버튼만). 추가 모드에서는 펼침. "문제 자동 분리" 버튼은 글자가 있을 때 주 버튼, 없을 때 비활성(사유 툴팁).
 f. 체크박스·토글도 토큰 스타일(가져오기 옵션 패널과 같은 모양)로 통일.

## 5C2-2. 붙여넣기: 줄 잇기 방식 선택
한국어 PDF 는 단어 중간에서 줄이 바뀌기도 해서, 잘린 줄을 공백으로 이으면 "처리할 수 없는 자 는?" 처럼 띄어쓰기가 끼어든다. 자동 판별은 불가능하므로 사용자가 고르게 한다.
- `importers/text` 옵션 `joinWrappedLinesWith?: 'space' | 'none'`(기본 'space'). 'none' 이면 붙여서 잇는다(단, 앞 줄이 문장 부호·닫는 괄호로 끝나거나 다음 줄이 여는 괄호·영문자/숫자로 시작하면 공백 유지 — 규칙은 문서화).
- 붙여넣기 패널에 "줄바꿈 잇기: 띄어쓰기로 / 붙여서" 선택(SegmentedControl 또는 Select). 바꾸면 즉시 다시 해석해 미리보기에 반영. 선택은 설정에 기억(settings 에 `pasteJoin` 추가 — validateSettings 갱신·테스트).
- 테스트: 두 방식, 예외 규칙, 선지·정답 줄은 잇지 않음.

## 5C2-3. 해설 붙여넣기 보강
- `parseExplanationText` 도 **잘린 줄 잇기**(같은 `joinWrappedLinesWith`)와 PDF 흔적 경고를 적용.
- 해설 머리의 정답 표기(`정답 ③`, `정답: ③`, `[정답] ③`, `답 ③`, 숫자 `정답 3`)를 **별도 필드 `answerLabels`** 로 뽑아내고 해설 본문에서는 그 줄을 제거. 결과: `{ number, explanation, answerLabels?: string[] }`.
- 편집기의 해설 짝짓기 표에 "정답" 열 추가: 문제에 정답이 비어 있으면 기본으로 채움(체크), 이미 있고 다르면 경고 표시(덮어쓰기는 사용자가 체크할 때만). main `bank.applyExplanations` 가 정답 적용도 처리(선지 ID 로 변환, 범위 밖이면 오류).
- 테스트: 각 표기, 정답 없는 해설, 잘린 줄, 정답 범위 밖.

## 5C2-4. 캡처 도구 보강
 a. 캡처 전에 창이 최대화·전체 화면이면 해제한 뒤 `setContentSize` (저장된 창 상태가 최대화면 캡처가 1920 폭으로 찍혔다). 캡처 모드에서는 창 상태를 settings 에 저장하지 않는다.
 b. 편집기의 준비 신호는 **현재 폼 내용으로 만든 미리보기가 그려진 뒤**에 설정(붙여넣기 직후 이전 미리보기가 찍혔다 — 디바운스 중이면 기다림). `add-paste` 첫 캡처가 10초 초과로 실패했다 → 붙여넣기 해석이 끝나고 미리보기가 그려질 때까지를 준비 조건으로.

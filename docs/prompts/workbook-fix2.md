# 작업: workbook 모듈 보정 2 (요약쪽 건너뛰기 완화, 선지 번호 오타 허용)

먼저 `AGENTS.md` 를 읽고 따른다. git commit/push 는 하지 않는다. `src/contracts/index.ts` 수정 금지. 실제 문제 파일(`문제 디비/`, *.pdf, *.docx)은 읽지 않는다(테스트는 가짜 문서만).
대상: `src/modules/workbook/question-book.ts` 와 테스트.

## 실제 책으로 확인한 문제
1. **표가 들어 있는 문제**: 번호 줄(`085`) 앞에 `KILLER POINT` 요약쪽이 오고, 번호 다음에 표 글자가 40줄 넘게 이어진 뒤에 `①` 이 나온다. 지난 보정에서 "`KILLER POINT` 를 만나면 다음 `^\d{3}$` + 40줄 안 `①` 이 있는 줄까지는 문제 시작을 찾지 않는다" 규칙을 넣었는데, 이 규칙 때문에 이 문제가 빠졌다(`WORKBOOK_NUMBER_GAP 85번~85번`).
2. **선지 번호 오타**: 책에 `① ② ③ ④ ④` 처럼 마지막 선지 번호가 잘못 찍힌 문제가 있다(`① ② ③ ③ ⑤` 도 있다). 지금은 `WORKBOOK_CHOICES_BROKEN` 오류로 문제가 버려진다.

## 고칠 내용
### A. 요약쪽 이후 문제 시작
- `KILLER POINT` 이후 문제 시작을 찾지 않는 구간 규칙을 **없앤다**. 문제 시작은 오직 "한 줄이 정확히 `^\d{3}$` 이고 **그 과목의 기대하는 다음 번호와 같다**" 로 판정한다(요약쪽에는 기대 번호와 같은 3자리 숫자만 있는 줄이 없다). 단, 기대 번호보다 큰 번호(+1~+5)를 받아들이는 기존 규칙은 그대로(그 뒤 40줄 안에 `①` 필요).
- 요약쪽이 문제 본문·선지에 붙지 않게 하는 **문제 끝 조건**(`KILLER POINT`, `출제 연도 기출 내용`, `제 N 장`, `PART`)은 그대로 유지한다.
- 본문이 8줄을 넘는 문제(표)는 지금처럼 `WORKBOOK_FIGURE_MISSING` 과 줄마다 문단.
- 40줄 안에 `①` 이 없는 기대 번호 문제는(그림 속 선지) 지금처럼 선지 없음으로 처리(`SKIPPED_NO_TEXT_CHOICES`).

### B. 선지 번호 오타 허용
- 한 문제에서 선지 마커(`①~⑤`)로 시작하는 선지가 2~5개이고 모든 마커가 `①~⑤` 중 하나이면, **마커의 숫자가 순서와 달라도 위치 순서대로 선지 1..n 으로 읽는다.** 이때 그 문제에 `WORKBOOK_CHOICE_LABEL_TYPO` (warn) `○○ N번: 선지 번호 표기가 순서와 달라(예: ④가 두 번) 나온 순서대로 읽었습니다. 선지 내용을 확인하세요.` 를 낸다.
- 정답 라벨(`③` 등)은 위치(1~5)로 해석한다(그대로 위치 번호). 선지 개수보다 큰 정답이면 기존 `SKIPPED_ANSWER_OUT_OF_RANGE`.
- 선지가 6개 이상이거나 마커가 `①~⑤` 이외이면 기존처럼 `WORKBOOK_CHOICES_BROKEN`.

## 테스트 (가짜 문서)
- `KILLER POINT` 요약쪽 직후에 표 글자 50줄 뒤 선지가 오는 문제가 인식되고, 앞뒤 문제와 섞이지 않는다.
- 마지막 선지가 `④` 가 두 번인 문제 → 5개 선지로 읽고 warn, 정답 `⑤` 가 5번째 선지.
- `① ② ③ ③ ⑤` 도 같다. 6개 이상이면 오류.
- 기존 테스트 통과(바뀐 동작에 맞게만 수정).
